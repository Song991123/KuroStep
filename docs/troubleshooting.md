# Troubleshooting

## 1. YouTube 재생 오류 메시지가 재생 전에도 표시됨

### 문제

곡을 플레이리스트에 추가만 했는데 YouTube iframe이 내부 error event를 발생시키면서 사용자에게 재생 실패 메시지가 표시되었습니다.

### 원인

YouTube 플레이어가 아직 사용자가 재생을 누르지 않은 상태에서도 cue/load 과정에서 error event를 발생시킬 수 있었습니다. 기존 구현은 이 이벤트를 항상 복구 대상으로 처리했습니다.

### 해결

`isPlayingRef`를 추가해 실제 재생 중일 때만 복구와 오류 메시지를 표시하도록 변경했습니다. 곡 추가나 화면 초기화 중 발생한 iframe 내부 오류는 사용자에게 바로 노출하지 않습니다.

## 2. 재생 위치 갱신으로 인한 리렌더 부담

### 문제

재생 위치가 250ms마다 React state로 갱신되면서 Tauri 다중 창과 가사/번역 요청이 겹칠 때 UI가 버벅일 수 있었습니다.

### 해결

재생 위치 갱신 주기를 500ms로 조정하고, 최신 position/duration은 ref에 보관하도록 변경했습니다. 이를 통해 가사 싱크는 유지하면서 전체 렌더링 부담을 줄였습니다.

## 3. 가사 요청 결과가 다른 곡 화면을 덮어씀

### 문제

A곡 가사 요청이 늦게 끝난 뒤 사용자가 B곡으로 넘어가면, A곡 결과가 뒤늦게 B곡 화면에 반영될 수 있었습니다.

### 해결

`lyricLoadRequestRef`로 요청 번호를 관리하여 최신 요청이 아닌 결과는 무시하도록 변경했습니다.

## 4. 번역 메모 요청 중복

### 문제

가사 줄이 바뀔 때마다 번역 조회/생성 요청이 반복되면서 네트워크 요청과 상태 갱신이 과해질 수 있었습니다.

### 해결

`translationCacheRef`와 `pendingTranslationRef`를 추가했습니다.

- 이미 캐시에 있는 줄은 서버 재조회 없이 사용
- 같은 줄에 대해 요청 중이면 중복 요청 방지

## 5. 작업 상태 카운트가 목록과 어긋남

### 문제

작업 목록은 갱신되었는데 상태 카운트가 이전 값처럼 보일 수 있었습니다.

### 해결

작업 발자국 위젯에서 별도 count 값을 신뢰하지 않고, 현재 `tasks` 배열을 기준으로 `TODO`, `DOING`, `DONE` 수를 즉시 계산하도록 변경했습니다.

## 6. 가사 조각 저장과 번역 메모 저장 순서

### 문제

현재 가사 조각을 저장할 때, 서버에 번역 메모가 저장되기 전에 로컬 조각이 먼저 저장될 수 있었습니다. 이 경우 저장한 조각과 번역 메모가 서로 어긋날 수 있었습니다.

### 해결

가사 조각 저장 시 서버 번역 메모 저장을 먼저 수행하고, 성공한 결과를 로컬 저장 조각에 반영하도록 변경했습니다. 서버 저장 실패 시 성공 메시지를 띄우지 않도록 방어했습니다.

## 7. macOS Gatekeeper 경고

### 문제

GitHub Releases에서 내려받은 macOS 앱은 Apple Developer ID로 공증되지 않았기 때문에 Gatekeeper 경고가 발생할 수 있습니다.

### 해결

포트폴리오 배포 단계에서는 ad-hoc signing을 적용했습니다. 테스트 사용자는 Finder에서 Control-click > Open 또는 quarantine 해제 명령으로 실행할 수 있습니다. 정식 배포 단계에서는 Apple Developer ID signing과 notarization을 적용할 예정입니다.
